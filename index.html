PUBLIC NETWORK MODE

Being straight about what this actually is: no website can detect whether a WiFi network is safe or not — browsers deliberately don't expose that to JavaScript, and anyone claiming otherwise is guessing. This isn't network detection; it's a manual "I'm somewhere risky" switch you flip yourself (a café, an airport, a shared/public computer) that tightens a few things while it's on:

  • Caps auto-lock at 1 minute, regardless of your normal setting
  • Forces lock-on-focus-loss on, even if you have it turned off above
  • Hides the breach-check button — not because it's unsafe (it's HTTPS either way), just to cut unnecessary network chatter while you're somewhere you don't trust
  • Shows a persistent on-screen reminder so you don't forget it's on

BIOMETRIC / PASSKEY QUICK UNLOCK (incl. Windows Hello)

Uses your device's fingerprint/face unlock, Windows Hello, or a security key (via the WebAuthn prf extension) to unlock without typing the master password.

Windows Hello specifically requires Windows 11 25H2 (build 26200.7840 or later — the February 2026 update) plus a recent Chrome, Edge, or Firefox. Older Windows/browser versions don't support it yet, full stop — that's a Microsoft/browser limitation, not something this app can work around. Mac (Touch ID/Face ID) and Android biometrics tend to work more broadly already. If it's not available, you'll just keep using the password — nothing else breaks.

BACKUP

Export downloads your still-encrypted vault as a JSON file. It's useless without your master password, but treat it like any encrypted secret.

TRANSFER PASSWORDS (CSV)

Move logins to or from other password managers (Chrome, Firefox, Bitwarden, 1Password, etc.) using the standard CSV format they all read. Unlike the backup above, this file is plaintext — anyone who opens it can read every password. Delete it as soon as you're done importing elsewhere.

The exported file is not encrypted. Only logins (title/url/username/password/notes) transfer this way — cards, notes, recovery codes and 2FA secrets stay in the encrypted backup only, since most other managers don't have a matching field for them.

CIPHERVAULT — EMERGENCY RECOVERY KIT

Generated . Keep this page somewhere physically secure — a safe, a locked drawer, a safety deposit box. Anyone holding this paper AND your backup file AND a copy of CipherVault can open your vault, so protect it like you would a spare house key.

1. What you need to recover this vault

  • Your encrypted backup file (Settings → Backup → Export Encrypted Backup) — a copy of the vault's ciphertext.
  • Your master password, written by hand below.
  • A running copy of CipherVault (this HTML file) — any recent version can read the backup; open it in any modern browser.

None of these three alone is enough. That's intentional — it's what makes the vault resistant to any single point of failure or theft.

2. Master Password

Write it by hand right before filing this away — don't print it digitally, and don't photograph this page.

3. How to recover

  1. Open a copy of CipherVault (cipher_vault.html) in a modern browser.
  2. On the lock screen, choose "Import Backup" and select the encrypted backup file.
  3. Enter the master password written above to unlock.

4. Notes on this vault

Vault key derivation: Argon2id (or PBKDF2 fallback) + AES-256-GCM. This is an experimental/testing build — treat this kit as a supplement to your own backup discipline, not a guarantee.
